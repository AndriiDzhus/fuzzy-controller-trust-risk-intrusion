## Необхідні дані для імплементації

### Для контролера Security Risk (Безпека):

Потрібні наступні специфікації:

1. **Вхідні змінні** (зазвичай 3-4 параметри):
   - Назва змінної (англ. і укр.)
   - Діапазон значень (min-max)
   - Од. виміру (якщо є)

2. **Терми для кожної вхідної змінної**:
   - Список лінгвістичних термів (наприклад: Low, Medium, High)
   - Параметри функцій приналежності:
     - Тип: трикутна / трапецієподібна
     - Координати точок (a, b, c, d для трапеції; a, b, c для трикутника)

3. **Вихідна змінна** (Security Risk - SR):
   - Діапазон значень
   - Терми та їх функції приналежності

4. **База правил** (IF-THEN):
   - Приклад: IF E is Low AND T is Low THEN SR is High
   - Всі комбінації правил

### Для контролера Intrusion Probability (Вторгнення):

Аналогічні дані як для Security Risk, але з власними параметрами:

1. Вхідні змінні
2. Терми функцій приналежності
3. Вихідна змінна (Intrusion Probability - IP)
4. База правил

## Формат надання даних

Рекомендований формат для надання даних:

```
### SECURITY RISK CONTROLLER

#### Вхідні змінні:
1. Назва: Authentication Strength (Сила аутентифікації)
   Діапазон: 0-100
   Терми:
   - Weak (0, 0, 30, 50)
   - Medium (30, 50, 70)
   - Strong (50, 70, 100, 100)

2. Назва: Encryption Level (Рівень шифрування)
   ...

#### Вихідна змінна:
Назва: Security Risk (Ризик безпеки)
Діапазон: 0-100
Терми:
- VeryLow (0, 0, 15, 25)
- ...

#### Правила:
1. IF AuthStrength is Weak AND Encryption is Weak THEN SR is VeryHigh
2. IF AuthStrength is Medium AND Encryption is Weak THEN SR is High
...
```

## Технічні детайлі

Архітектура аналогічна існуючому Probability Controller:
- Fronend: HTML форми → AJAX запити
- Backend: Express API → FuzzyController клас
- Відображення: Canvas графіки функцій приналежності
- Результати: Обчислене значення + домінуючий терм

Всі необхідні файли підготовлені та очікують конфігурації.
