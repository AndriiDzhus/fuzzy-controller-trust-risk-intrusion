# Навчальні дані контролерів

Апка працює з **одним файлом на контролер**:

| Файл | Контролер, метод | Рядків | Колонки |
|---|---|---|---|
| `security.csv` | Безпека, ANFIS | 200 (140 `train` / 60 `test`) | `EC, TP, Lat, SR, split, row_id` |
| `intrusion.csv` | Вторгнення, ГА | 240 (160 `train` / 40 `validation` / 40 `test`) | `NP, Rate, We, IP, label, category, split` |

Саме ці файли віддає кнопка «Отримати .xlsx» у блоці «Навчання моделі» (весь файл
або перші N рядків із збереженням часток `split`), і саме на них працює кнопка
«Навчити на датасеті за замовчуванням». Сценарій для викладача:

1. Отримати `.xlsx`, відкрити в Excel.
2. Змінити цільову колонку (`SR` або `IP`), дописати чи прибрати рядки.
   Колонку `split` краще лишити — тоді тест залишається тим самим і результати
   різних спроб можна порівнювати. Без неї поділ 70/15/15 (70/30) робиться
   автоматично (seed 42).
3. Завантажити файл назад — навчання стартує одразу; порівняти з експертною
   моделлю і застосувати.

Для Безпеки всі вхідні точки файла (train і test) є ще й точками **покриття**:
навчені трикутники не можуть лишити жодну з них без спрацьованого правила.

Малі файли будує `scripts/data/make_app_datasets.py` (`npm run data:app`) з повних
вибірок у `data/full/`: для Безпеки — 200 з 250 розмічених рядків зі збереженням
частки кожного домінантного правила (рідкісні правила беруться цілком); для
Вторгнення — по 30 рядків на категорію (20 / 5 / 5 з train / validation / test
CICIoT2023), рівномірно по діапазону Rate, усі 34 класи. Скрипт детермінований.

Скрипти навчання `npm run train:security` і `npm run train:intrusion` за
замовчуванням теж беруть `data/*.csv`; з прапорцем `--full` — повні вибірки
нижче (цифри для дисертації).

## Повні вибірки: `full/`

Їх створює `scripts/data/prepare_datasets.py` з вихідних файлів (у репозиторій
вони не входять):

```bash
npm run data:prepare
# або з явним шляхом:
python3 scripts/data/prepare_datasets.py --datasets <папка DATASETS>
```

Скрипт детермінований (seed 42). Він **ніколи не перезаписує** файли, які
заповнює експерт (`security_labeling.csv`, `label_to_ip.csv`). Щоб перебудувати й
їх, додайте `--force`. У файлах залишено лише вхідні величини контролерів.

### Безпека (ANFIS): `full/security/`

| Файл | Що містить |
|---|---|
| `security_6g.csv` | усі 1000 рядків 6G IoT Intelligent Management Dataset: `row_id, EC, TP, Lat` |
| `security_labeling.csv` | 250 рядків для експертної розмітки (див. нижче) |

Колонки `security_labeling.csv`:

| Колонка | Значення |
|---|---|
| `row_id` | номер рядка у вихідному `6G_IoT_Beamforming_Dataset.csv` (з 1) |
| `EC` | Energy Consumption, кВт·год/ГБ (у даних 0,01–0,05) |
| `TP` | Transmit Power, дБм (у даних 10–35) |
| `Lat` | Latency, мс (у даних 1–10) |
| `SR_base` | довідково: що видає поточна експертна модель (6 правил) |
| **`SR_expert`** | **заповнює експерт**: індекс ризику безпеки 0–100 |
| `split` | `train` (174 рядки) або `test` (76 рядків), не змінювати |
| `dominant_rule` | правило з найбільшою вагою: так рядки розподілено між 6 правилами |

#### Як заповнювати `SR_expert`

Число від 0 до 100 (можна дробове). Орієнтири — синглтони вихідної величини:

| SR | Терм |
|---|---|
| 0 | Немає |
| 20 | Дуже малий |
| 40 | Малий |
| 60 | Середній |
| 80 | Великий |
| 100 | Дуже великий |

Проміжні значення (наприклад, 35 або 72) допустимі й корисні. `SR_base` можна
використовувати як відправну точку або ігнорувати: ANFIS навчається саме на
відхиленнях вашої оцінки від неї. Якщо оцінки збігатимуться з `SR_base`, навчання
нічого не змінить. Рядки з порожнім `SR_expert` пропускаються, але для навчання
потрібно щонайменше 30 заповнених рядків у `train`.

Відкривати й зберігати файл можна в Excel або LibreOffice як CSV
(роздільник — кома, десяткова крапка).

#### Запропоновані значення (`SR_proposed`)

`scripts/data/propose_security_labels.py` додає колонку `SR_proposed` — оцінку за
матрицею ризику з літературними орієнтирами (опис у заголовку скрипта), і
колонку `zones` — зону кожного входу (EC, TP, Lat): 0 норма, 1 підвищений, 2 критичний.
Це чернетка: перегляньте, виправте й перенесіть у `SR_expert` (або запустіть
скрипт з `--fill`, щоб скопіювати її в порожні клітинки `SR_expert`).

```bash
python3 scripts/data/propose_security_labels.py          # лише SR_proposed
python3 scripts/data/propose_security_labels.py --fill   # + заповнити порожні SR_expert
```

`SR` у `data/security.csv` = `SR_expert`, якщо заповнено, інакше `SR_proposed`,
інакше `SR_base`. Після правок тут перебудуйте малий файл: `npm run data:app`.

Навчання на повному файлі (потрібен `SR_expert`):

```bash
npm run train:security -- --full
```

Результат записується в `src/controllers/trained/security.json`. Після цього
на сторінці «Безпека системи» стає доступним перемикач «Навчена (ANFIS)».

### Вторгнення (генетичний алгоритм): `full/intrusion/`

Джерело — CICIoT2023, версія MERGED (`CICIOT23/train|validation|test`), бо лише
вона містить `Number`, `Rate`, `Weight` і мітку `label`.

| Файл | Що містить |
|---|---|
| `intrusion_train.csv` | 4000 рядків із `train.csv`: 500 на кожну з 8 категорій |
| `intrusion_validation.csv` | 1600 рядків із `validation.csv`: 200 на категорію |
| `intrusion_test.csv` | 1600 рядків із `test.csv`: 200 на категорію |
| `label_to_ip.csv` | **заповнює експерт**: еталонне IP для кожного з 34 класів трафіку |

Колонки вибірок: `NP` (= Number), `Rate` (= Rate, пакетів/с, без змін), `We`
(= Weight), `label` (клас трафіку), `category` (одна з 7 категорій атак або Benign).
Усередині категорії рядки розподілено рівномірно між класами. Логарифм
`lg(1 + Rate)` застосовує скрипт навчання, а не цей файл.

#### Як заповнювати `label_to_ip.csv`

`IP_target` — вірогідність вторгнення 0–100 для всього трафіку цього класу.
Орієнтири — центри термів вихідної величини: 0 «відсутня», 30 «мала»,
60 «середня», 100 «велика». Проміжні значення допустимі.

Чернетку заповнено за категоріями: Benign 0, Recon 30, Spoofing / BruteForce / Web 60,
DoS / DDoS / Mirai 100, Backdoor_Malware 100. Перевірте й виправте її, а потім
перебудуйте малий файл (`npm run data:app`): у `data/intrusion.csv` значення `IP`
вже підставлено з цієї таблиці.

Навчання на повних вибірках:

```bash
npm run train:intrusion -- --full   # близько 3 хв; параметри: --generations, --population, --seed
```

Результат записується в `src/controllers/trained/intrusion.json`.

#### Особливість CICIoT2023 (варто згадати в тексті роботи)

У версії MERGED `Number` майже дискретний: 9,5 для «100-пакетних» вікон
(DoS, DDoS, Mirai, VulnerabilityScan) і 5,5 або 13,5 для «10-пакетних» (Benign,
Recon, Web, Spoofing, BruteForce). `Weight` однозначно визначається через `Number`
(5,5 → 38,5; 9,5 → 141,55; 13,5 → 244,6; кореляція 0,9995). NP і We фактично
несуть одну й ту саму інформацію, а Benign від Recon, Web і Spoofing контролер
відрізняє лише за Rate. Звідси межа точності: RMSE близько 22 при еталоні 0–100.
